## 1. 📌 What is a Wireframe?

A **wireframe** is a simple visual representation or **blueprint of a webpage or application**.

It focuses mainly on:

* 📐 Layout
* 🧭 Navigation
* 📝 Content placement
* 🔘 Buttons
* 🖼️ Images
* 📋 Forms
* 🧩 User-interface structure

A wireframe usually does **not** focus on final colors, animations, graphics, or detailed visual design.

### Simple idea

```text
Requirement
     ↓
Wireframe
     ↓
Visual Layout
     ↓
Design
     ↓
Development
     ↓
Final Website
```

---

# 2. 🤔 Why Do We Need Wireframes?

Before writing HTML, CSS, and JavaScript, we should first decide:

> **"Where should each element be placed?"**

For example, an online bookstore may need:

```text
┌─────────────────────────────────────────┐
│               LOGO                      │
│       Home | Login | Cart               │
├─────────────┬───────────────────────────┤
│             │                           │
│ Categories  │       Products            │
│             │                           │
│ • CSE       │   ┌────┐ ┌────┐ ┌────┐  │
│ • ECE       │   │ 📕 │ │ 📕 │ │ 📕 │  │
│ • Civil     │   └────┘ └────┘ └────┘  │
│             │                           │
├─────────────┴───────────────────────────┤
│                Footer                   │
└─────────────────────────────────────────┘
```

This is a **wireframe**.

---

# 3. 🅱️ What is Balsamiq?

**Balsamiq** is a wireframing and user-interface design tool used to create **low-fidelity mockups**.

It helps designers and developers quickly visualize how a webpage or application might be arranged.

### In simple words

> **Balsamiq helps us draw the structure of a website before we code it.**

---

# 4. 🎯 Main Purpose of Balsamiq

Balsamiq is mainly used for:

```text
Idea
 ↓
Page Layout
 ↓
Wireframe
 ↓
Discussion
 ↓
Changes
 ↓
Final Design
 ↓
Development
```

It allows a team to discuss the **structure and user experience** before spending time on detailed implementation.

# 7. ✏️ Low-Fidelity Wireframe

Balsamiq is commonly used for **low-fidelity wireframes**.

### What does low-fidelity mean?

It means the design is:

* Simple
* Quick
* Rough
* Focused on structure
* Easy to change

Example:

```text
┌───────────────────────┐
│       LOGO            │
├───────────────────────┤
│ Home | About | Login  │
├───────────────────────┤
│                       │
│      IMAGE            │
│                       │
├───────────────────────┤
│     Product Name      │
│     Description       │
│     [Buy Now]         │
└───────────────────────┘
```

We are **not worrying about final colors or exact graphics**.

---

# 8. 🎨 Wireframe vs Final Website

| Wireframe         | Final Website                   |
| ----------------- | ------------------------------- |
| Basic structure   | Complete design                 |
| Simple appearance | Colors and branding             |
| Focuses on layout | Focuses on complete UI          |
| Quick to create   | Takes more development time     |
| Easy to modify    | Changes may require development |
| Low fidelity      | Higher fidelity                 |

### Remember

> **Wireframe = Blueprint**

> **Website = Final Building**

# 15. 🔄 Wireframe to HTML/CSS

A wireframe can be converted into an actual webpage.

### Wireframe

```text
┌─────────────────────────┐
│          HEADER         │
├─────────────────────────┤
│       NAVIGATION        │
├─────────────────────────┤
│                         │
│        CONTENT          │
│                         │
├─────────────────────────┤
│          FOOTER         │
└─────────────────────────┘
```

### HTML structure

```html
<header>
    Header
</header>

<nav>
    Navigation
</nav>

<main>
    Content
</main>

<footer>
    Footer
</footer>
```

### CSS

```css
header {
    height: 100px;
}

nav {
    height: 50px;
}

main {
    min-height: 400px;
}

footer {
    height: 100px;
}
```

So:

```text
Balsamiq Wireframe
        ↓
     Layout
        ↓
HTML Structure
        ↓
CSS Styling
        ↓
Final Website
```

# 16. 🆚 Wireframe vs Prototype vs Final Product

| Stage         | Purpose                          |
| ------------- | -------------------------------- |
| Wireframe     | Plan structure and layout        |
| Prototype     | Demonstrate interaction and flow |
| Final Product | Fully developed application      |

### Simple example

```text
Wireframe
   ↓
"Where should the Login button be?"

Prototype
   ↓
"What happens when I click Login?"

Final Website
   ↓
"Login actually works."
```

# 17. ✅ Advantages of Balsamiq Wireframes

### 1. Saves Development Time

Problems can be identified before coding.

### 2. Easy to Modify

Changing a rough layout is easier than changing a completed website.

### 3. Better Communication

Team members can discuss the same visual design.

### 4. Helps Understand User Flow

We can plan how users move from one page to another.

### 5. Focuses on Structure

The team can discuss functionality and layout without being distracted by final colors and visual details.

---

# 18. ⚠️ Limitations

Wireframes are not the final website.

They generally do not show:

* Final colors
* Exact typography
* Complete animations
* Final visual styling
* Fully implemented functionality

Therefore:

```text
Wireframe ≠ Final Website
```
